# セカンドブレイン拡張計画

iPhone/iPadの音声入力アプリごとに、それぞれ別のセカンドブレイン連携を作る計画。

## 作りたいもの（2系統）

1. **ジャーナル版セカンドブレイン**
   - 入力元: iPhoneの「ジャーナル」アプリの音声記録（現状はテキスト直接入力で代用）
   - 連携方法: iOS Shortcuts（「GitHub テスト送信」）→ GitHub Contents API
     → `vault/99-Inbox/` に送信
   - 状況（2026-10-01時点）:
     - ✅ GitHub Personal Access Token発行、Shortcutsからの認証・接続
     - ✅ 本文（指定入力）・captured日付が正しくファイルに記録される
     - ✅ 実際にGitHubへのコミットが複数回成功している
     - ❌ **未解決の不具合**: ファイル名用の「日付を書式設定」アクションの
       出力が、URLに挿入すると実行時に空文字列になる。そのため送信の
       たびに`vault/99-Inbox/.md`という同じ名前のファイルに上書きされて
       しまう（中身は毎回最新の内容に更新される）。
       - 試したが直らなかったこと: カスタム書式の再入力、
         アポストロフィを使わない書式(`yyyy-MM-dd-HH-mm-ss`)への変更、
         参照の消去→再挿入、UUID/乱数アクションへの切り替え（日本語版
         Shortcutsで該当アクションが検索でヒットせず断念）
       - 次回試すと良さそうなこと: 「テキストを置き換え」アクションで
         `現在の日付`の生の文字列から`/`や`:`を置換してファイル名を作る方式
         （UUID探しより検索しやすい可能性）。または一度ショートカットを
         作り直す。
     - 本文・日付の仕組み自体はWhisper文字起こし済みの`.md`が
       `vault/99-Inbox/`に届く前提の設計（`docs/ios-journal-sync.md`、
       `scripts/transcribe_inbox.py`）と同じ形式なので、ファイル名問題が
       直れば通常運用に乗る見込み。

2. **メモアプリ版セカンドブレイン**
   - 入力元: iPadの「メモ」アプリの音声記録
   - 連携方法: 未設計（ジャーナル版とは別形式、または別アプリとして
     切り出す想定）
   - 状況: 未着手

## 進め方

- 先に①ジャーナル版を完成させる（iOS Shortcutsの実機設定 → 動作確認）。
- ①が安定してから、②メモアプリ版の設計に着手する。
- 2つは同じ`vault/99-Inbox/`を共有するか、別の受け皿フォルダに分けるかは
  ②の設計時に決める。
