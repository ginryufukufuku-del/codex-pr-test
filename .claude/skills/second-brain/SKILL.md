# セカンドブレイン運用スキル

このリポジトリの `vault/` は Obsidian Vault で、PARA 方式
（Projects / Areas / Resources / Archive）+ Journal で構成されている。

## Inbox（iOS Journalからの取り込み）を処理する

`vault/99-Inbox/` には iOS Shortcuts 経由で送られた、Journalアプリの音声メモが
置かれている（`.gitkeep` と `README.md` 以外のファイル）。文字起こしは
Journalアプリではなく Whisper で自動化している。
セッション開始時やユーザーが「Inboxを処理して」と言ったときに以下を行う。

0. `vault/99-Inbox/` に音声ファイル（`.m4a` 等）が残っていたら、まず
   `python3 scripts/transcribe_inbox.py` を実行して自動文字起こしする
   （`OPENAI_API_KEY` が未設定ならユーザーに設定を依頼する）。
   これにより音声ファイルは削除され、同名の `.md` が作られる。
1. `vault/99-Inbox/` 内の `.md` ファイルを読む。ファイル名がタイムスタンプ
   （`YYYY-MM-DDTHH-mm-ss.md`）、フロントマターの `captured` がキャプチャ日時。
2. `captured` の日付部分に対応する `vault/00-Journal/YYYY-MM-DD.md` を
   （無ければテンプレートから）作成し、本文を要約・整形して追記する
   （音声の書き起こしそのままではなく、「今日の出来事」「気づき・アイデア」
   「タスク」など該当セクションに振り分ける。Whisperの誤認識と思われる
   不自然な箇所は文脈から補正してよい）。
3. 内容にプロジェクト/領域/参照情報が含まれる場合は、下記「ノートを作る」の
   手順でノートを作成・更新し、ジャーナルからリンクする。
4. 処理が終わったInboxファイルは削除する。
5. 複数ファイルが同じ日付にまたがる場合は、同じジャーナルノートにまとめて追記する。

Shortcuts側のセットアップ手順とWhisperの設定は `docs/ios-journal-sync.md` を参照。

## デイリージャーナルを書く/追記する

1. 今日の日付のファイル `vault/00-Journal/YYYY-MM-DD.md` が無ければ、
   `vault/00-Journal/templates/Daily.md` を元に作成する（`{{date}}` は実際の日付に置換）。
2. ユーザーの発言内容を該当セクション（出来事・気づき・タスクなど）に追記する。
3. 内容から独立したトピック（プロジェクト、継続的な関心事、参照情報）が
   見つかったら、下記の「ノートを作る」手順で `01-Projects` / `02-Areas` /
   `03-Resources` にノートを作り、ジャーナルの「関連ノート」セクションに
   `[[ノート名]]` 形式でリンクする。

## ノートを作る（Projects / Areas / Resources）

- 期限や完了条件がある → `01-Projects/<ノート名>.md`
- 継続的に責任を持つ領域（健康、学習、仕事など） → `02-Areas/<ノート名>.md`
- 後で参照したい知識・資料・トピック → `03-Resources/<ノート名>.md`
- YAML フロントマターに `tags`, `created`（作成日）を付ける。
- 既存ノートと関連する場合は `[[既存ノート名]]` でリンクし、孤立ノートを作らない。

## アーカイブする

完了したプロジェクトや使わなくなったノートは、内容を変更せず
`04-Archive/` へ移動する。移動元へのリンクが残っている場合は、リンク先を
新しいパスに更新する。

## 注意点

- ノートのファイル名はそのままリンク名（`[[ファイル名]]`）になるため、
  日本語でも英語でも簡潔で一意な名前にする。
- 1ノート1トピックを原則とし、ジャーナルの雑多な内容をそのまま
  Resources に転記しない（要約・構造化してから書く）。
