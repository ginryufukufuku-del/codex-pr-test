# セカンドブレイン運用スキル

このリポジトリの `vault/` は Obsidian Vault で、PARA 方式
（Projects / Areas / Resources / Archive）+ Journal で構成されている。

## Inbox（iOS Journalからの取り込み）を処理する

`vault/99-Inbox/` には iOS Shortcuts 経由で送られた、Journalアプリの音声メモが
置かれている（`.gitkeep` と `README.md` 以外のファイル）。文字起こしは
Journalアプリではなく Whisper で自動化している。
セッション開始時やユーザーが「Inboxを処理して」と言ったときに以下を行う。

0. `vault/99-Inbox/` に音声ファイル（`.m4a` 等）が残っていたら、まず
   `python3 scripts/transcribe_inbox.py` を実行してローカルWhisperで
   自動文字起こしする（`faster-whisper` 未インストールならユーザーに
   `pip install -r scripts/requirements.txt` を依頼する）。
   これにより音声ファイルは削除され、同名の `.md` が作られる。
1. `vault/99-Inbox/` 内の `.md` ファイルを読む。ファイル名がタイムスタンプ
   （`YYYY-MM-DDTHH-mm-ss.md`）、フロントマターの `captured` がキャプチャ日時。
2. `captured` の日時を使って `vault/00-Journal/entries/YYYY-MM-DD-HHmm.md` を
   `templates/Entry.md` から作成し、書き起こし本文を記録する（Whisperの誤認識と
   思われる不自然な箇所は文脈から補正してよい）。対応する
   `vault/00-Journal/YYYY-MM-DD.md` が無ければテンプレートから作成し、
   「今日の記録」にこの個別ノートへのリンクを追加する。気づき・タスクが
   含まれる場合は該当セクションにも要約を追記する。
3. 内容にプロジェクト/領域/参照情報が含まれる場合は、下記「ノートを作る」の
   手順でノートを作成・更新し、ジャーナルからリンクする。
4. 処理が終わったInboxファイルは削除する。
5. 複数ファイルが同じ日付にまたがる場合は、同じジャーナルノートにまとめて追記する。

Shortcuts側のセットアップ手順とWhisperの設定は `docs/ios-journal-sync.md` を参照。

## デイリージャーナルを書く/追記する（音声入力1回＝1ノート方式）

このチャットはセカンドブレイン専用ではなく、アプリ開発や技術的な質問など他の
用途にも使われる。そのため、**発言内容が「個人的な出来事・気づき・感想・日々の
振り返り」に該当すると判断できたときだけ**ジャーナルに記録する。アプリ・コードの
実装依頼、技術的な質問、ツールの使い方相談、作業指示などは記録しない。
判断に迷う場合は記録せず、通常の応答のみ行う。

ジャーナル対象と判断した発言は、1回ごとに独立したノートとして保存する。
デイリーノート本体は本文を持たず、その日の個別ノートへのリンク集として機能する。

1. `vault/00-Journal/templates/Entry.md` を元に、現在日時のファイル
   `vault/00-Journal/entries/YYYY-MM-DD-HHmm.md` を作成し、`{{date}}`/`{{time}}` を
   実際の日時に、`{{本文}}` をユーザーの発言内容に置き換える
   （誤字脱字や音声認識特有の不自然な箇所は文脈から補正してよいが、
   内容の要約・省略はしない＝生の記録として残す）。同じ分に複数回入力があれば
   ファイル名末尾に `-2` 等を付けて重複を避ける。
2. 今日の日付のデイリーノート `vault/00-Journal/YYYY-MM-DD.md` が無ければ、
   `vault/00-Journal/templates/Daily.md` を元に作成する。
3. デイリーノートの「今日の記録」セクションに、作成した個別ノートへの
   リンク `[[YYYY-MM-DD-HHmm]]`（内容が分かる一言を添えてよい）を時刻順に追加する。
   本文そのものはここには書かない。
4. 個別ノートの内容に気づき・タスクが含まれる場合は、デイリーノートの
   「気づき・アイデア」「タスク」セクションに要約を追記する。
5. 内容から独立したトピック（プロジェクト、継続的な関心事、参照情報）が
   見つかったら、下記の「ノートを作る」手順で `01-Projects` / `02-Areas` /
   `03-Resources` にノートを作り、個別ノート・デイリーノート双方の
   「関連ノート」セクションに `[[ノート名]]` 形式でリンクする。

## ノートを作る（Projects / Areas / Resources）

- 期限や完了条件がある → `01-Projects/<ノート名>.md`
- 継続的に責任を持つ領域（健康、学習、仕事など） → `02-Areas/<ノート名>.md`
- 後で参照したい知識・資料・トピック → `03-Resources/<ノート名>.md`
- YAML フロントマターに `tags`, `created`（作成日）を付ける。
- 既存ノートと関連する場合は `[[既存ノート名]]` でリンクし、孤立ノートを作らない。

## アーカイブする

完了したプロジェクトや使わなくなったノートは、内容を変更せず
`04-Archive/` へ移動する。移動元へのリンクが残っている場合は、リンク先を
新しいパスに更新する。

## 注意点

- ノートのファイル名はそのままリンク名（`[[ファイル名]]`）になるため、
  日本語でも英語でも簡潔で一意な名前にする。
- 1ノート1トピックを原則とし、ジャーナルの雑多な内容をそのまま
  Resources に転記しない（要約・構造化してから書く）。
